# Content Farm's Docs Get Missing Dates and Authors, and Statuses That Say Where Work Stands

## Why Care?

[[2026-11-01_01]] made `content-farm/context-v/` an Open Knowledge Format bundle. This pass brings the same docs up to the Context Vigilance Kit's baseline frontmatter. A dashboard grouping the plugin family's work by status can now tell what's done, what's in flight, and what's waiting on a decision, because every status uses one vocabulary.

## What's New?

- **Eight docs gain a `date_modified`** and two a `date_created`. The values come from git, not today: each file's last commit before the sweep, or its first.
- **Six docs gain `authors`**, from their only human committer.
- **Fifteen statuses move onto the kit's vocabulary:**
  - Re-cased or renamed with no reading: `open` → `Open` (3), `deferred` → `Deferred`, `In Progress` → `Implementing`, `Authoritative` → `Active` (3), and `Resolved (…)` → `Resolved`, since the body already says which plugins made it into the directory.
  - Decided by reading each doc and checking the plugin repos:
    - Three explorations go from `Exploration` to `Draft`.
    - The per-directory profile templates spec goes from `spike` to `Shipped`; the spike landed in Perplexed on 2026-05-09 and shipped in its 0.3.0 templates.
    - The Metafetch source-notes spec goes to `Partially-Shipped`: Phases 1, 2, and 2.5 shipped, Phases 3 and 4 haven't.
    - Cite Wide's inline-dedupe plan goes from `proposed` to `In-Review`. It was built and reverted the same day, so it wants a decision before anyone builds it again.
- **Tags:** Moving-Beyond-Simple-API-Calls's tags are Title-Cased, and `cite-wide` becomes `Cite-Wide` in one prompt. The repo-name tags `cite-wide` and `Content-Farm` come off five docs whose bodies already name the repo.
- **One bare-string `augmented_with` becomes a one-item list**, the string kept word for word.

## Under the Hood

- Part of the tree-wide OKF sweep; see the Context Vigilance Kit's plan, [[Retrofit-Every-Repo-to-OKF-Then-the-Kit-Frontmatter]].
- Every edit was made by hand. No body line changed, no key was deleted, and no `publish` or lede value moved.
- Every doc already had a `site_uuid` and `hex_code`, so no IDs were minted.
- The new `date_modified` values all point at 2026-08-18, a bulk frontmatter commit. That's still the last time each file changed, which is what the field records.
- Left for a later pass: the companion fields the new statuses call for (`deferral_note`, `date_first_published`, a `## Remaining work` section), and the loose root doc, which still says `Authoritative`.
