# Plugin Docs Now Reach the Splash Without a Rebuild

## Why Care?

The splash shows every plugin's changelog, release notes, and specs in one place. But it only knew about them when someone remembered to run a sync and commit the result. Nobody had since August, so 59 of 154 documents were missing, including the latest Perplexed, Metafetch, and Cite Wide releases.

A new document in an existing collection shouldn't need a deployment at all. Now it doesn't.

## What's New?

- **New documents just appear.** Push a markdown file to `changelog/` or `context-v/` in any plugin, and the page exists.
- **New plugins do too.** The list of plugins comes from `.gitmodules`, read the same way.
- **The sitemap and `llms.txt` keep up.** They're written per request, so search engines and LLMs see new documents as soon as visitors do.
- **The splash is moving to Vercel.** GitHub Pages only serves files that already exist, so it can't do this. Old `lossless-group.github.io/content-farm/` links will redirect to the same page at the new address.

## How It Works

`changelog` and `context-v` are now [Astro live collections](https://docs.astro.build/en/guides/content-collections/), fetched when a page is requested rather than when the site is built.

That could have been slow and could have burned through GitHub's rate limit. Three things keep it cheap:

- **Checking for changes is free.** GitHub doesn't count a conditional request that returns 304, so asking "has this branch moved?" costs nothing when it hasn't.
- **Only what changed gets downloaded.** Each file's blob hash tells us whether we already have it.
- **Files are read at an exact commit,** which skips the 5-minute cache GitHub keeps on branch URLs.

The first request on a fresh server takes under 3 seconds to load all 15 repos. After that it comes from memory, and the CDN serves most visitors before the server is involved at all.

## What Happens When GitHub Fails

The old sync wiped its folder first and only warned if a plugin failed, so a bad run could quietly remove pages. Now, a repo that can't be read keeps its last good copy. If there's nothing to serve, an entry page returns a 503, and nothing built during a failure gets cached.

## What's Next?

- Create the Vercel project and set its token.
- Promote to `main`, which switches GitHub Pages over to the redirect.
