# Plugin Docs Now Reach the Splash on Their Own

## Why Care?

The splash shows every plugin's changelog, release notes, and specs in one place. But it only knew about them when someone remembered to run a sync and commit the result. Nobody had since August, so 59 of 154 documents were missing, including the latest Perplexed, Metafetch, and Cite Wide releases.

Publishing a document shouldn't depend on anyone remembering a second step. Now it doesn't.

## What's New?

- **New documents just appear.** Push a markdown file to `changelog/` or `context-v/` in any plugin, and the page exists after the next scheduled build.
- **New plugins do too.** The list of plugins comes from `.gitmodules`, read the same way.
- **The sitemap and `llms.txt` keep up.** They're built with the pages, so search engines and LLMs see every document.
- **The splash stays on GitHub Pages,** at the same address.

## How It Works

Every 15 minutes, a GitHub Actions workflow rebuilds the site. The build asks GitHub for each repo's latest commit and file list, then downloads the documents at that exact commit. The site's code comes from `main`, and the documents come from each repo's branch tip, so publishing a document never needs a code change.

GitHub can delay scheduled runs, so 15 minutes is a typical wait rather than a promise. To publish sooner, run the workflow by hand.

## What Happens When GitHub Fails

The old sync wiped its folder first and only warned if a plugin failed, so a bad run could quietly remove pages. Now, a repo that can't be read fails the build, and Pages keeps serving the last good site.

## Why Not Vercel?

We first built this with Astro live collections on Vercel, where a new document appears in about a minute with no rebuild at all. We stayed on Pages instead, which keeps the site where it is and adds no new host. That version is in commit `ffa1f99` if we ever need it.
