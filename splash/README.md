# content-farm/splash

GitHub Pages splash for the [content-farm](https://github.com/lossless-group/content-farm) pseudomonorepo.

Live: <https://lossless-group.github.io/content-farm/>

## What this is

A small Astro site that:

1. Greets visitors with a hero, philosophy, and a curated gallery of the nine plugins under `plugin-modules/`.
2. Renders the parent's `context-v/` and (when present) `changelog/` as readable archives.
3. Deploys for free off GitHub Pages on push to `main`.

It is **not** the eventual marketing site for content-farm — when that exists, it'll live elsewhere with its own custom domain. The directory is named `splash/` precisely to keep that linguistic space open.

## Local dev

```bash
pnpm install --ignore-workspace
pnpm dev
```

The dev server respects `base: '/content-farm/'`, so visit <http://localhost:4321/content-farm/>.

> `--ignore-workspace` is required because the parent `lossless-monorepo` declares a pnpm workspace that doesn't include this site; the splash installs its own deps independently.

## The roll-up flow

The splash aggregates each plugin submodule's `changelog/` and `context-v/` into one feed — but the build itself doesn't fetch anything. **A human runs `pnpm rollup:sync` deliberately**; the rolled-up content lands in `splash/src/rollup/`, gets committed, and from then on the build is pure file IO.

```bash
pnpm rollup:sync
git add src/rollup/
git commit -m "sync(rollup): refresh from <reason>"
git push
```

This is a deliberate design choice (vs. fetching at every build):

| | Sync-on-build | Sync-on-demand (current) |
|---|---|---|
| Build time | 30s (API calls) | 1s (file IO) |
| CI auth | needs `GITHUB_TOKEN` | none |
| Rate limits | every build counts against 5000/hr | sync runs at human cadence |
| Diff visibility | invisible — content materializes only at render | git diff shows what rolled up |
| Determinism | depends on remote state at build time | what you commit is what deploys |

### When to run `rollup:sync`

- A plugin shipped a noteworthy `changelog/` entry you want surfaced.
- You bumped a submodule pointer.
- Periodically (e.g. weekly) to catch upstream drift — could be cron-ed locally.

### Auth for the sync

The sync script reads `GITHUB_TOKEN` or `GITHUB_API_TOKEN` from your shell or `splash/.env`:

```bash
# splash/.env
GITHUB_API_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxx
```

Or grab it from your `gh` CLI:

```bash
echo "GITHUB_API_TOKEN=$(gh auth token)" >> splash/.env
```

Anonymous mode works at 60 req/hr if you don't want to bother with a token; one full sync uses ~60-70 calls, so you'll have to wait an hour between syncs. With a token, 5000/hr — effectively unlimited.

## Where things live

| Path | Purpose |
|---|---|
| `src/pages/index.astro` | Hero, plugin gallery, philosophy, latest changelog |
| `src/pages/changelog/` | List + detail for the union of `../changelog/` (local) and `src/rollup/changelog/` (synced submodules) |
| `src/pages/context-v/` | List + detail for `../context-v/` (local) ∪ `src/rollup/context-v/` (synced submodules) |
| `src/content/plugin-highlights/*.md` | Curated plugin cards. Edit these to update the gallery. |
| `src/rollup/` | Synced submodule content. Generated by `pnpm rollup:sync`. **Do not edit by hand** — gets wiped on next sync. |
| `src/content.config.ts` | Collection definitions; uses a small `unionLoader` to read local + rollup. |
| `src/loaders/` | The fetcher (`rollupFetch.ts`), GitHub Content API client, `.gitmodules` parser, and minimal frontmatter parser (~150 lines, no `gray-matter`). |
| `scripts/rollup-sync.ts` | The CLI script invoked by `pnpm rollup:sync`. |
| `src/layouts/BaseLayout.astro` | Global tokens, fonts, head, body shell |
| `src/components/` | PluginCard, etc. |

### Path aliases

`tsconfig.json` declares short aliases so loader code never needs guesswork relative paths: `@components/*`, `@layouts/*`, `@loaders/*`, `@content/*`, `@pages/*`, `@/*`. Use them.

## Curating the plugin gallery

Each plugin gets one markdown file under `src/content/plugin-highlights/`. Frontmatter:

```yaml
---
title: cite-wide              # display name
lede: One-sentence pitch.     # appears under the title
order: 10                     # integer, lower sorts first
status: Stable                # Stable | Beta | Alpha | Experiment
repo: https://github.com/lossless-group/cite-wide
icon: 📚                      # emoji or path under public/
featured: true                # featured cards take a wider tile in the grid
tags: [Citations, Research]
---

Long-form description in markdown. Renders as the card's expanded body.
```

`order` ties are broken alphabetically by filename — never throws.

## Deploy

`.github/workflows/pages.yml` (in the parent repo root) builds this site on push to `main` and deploys via the `actions/deploy-pages` action. Configure GitHub Pages on the `content-farm` repo to "GitHub Actions" as the source.
